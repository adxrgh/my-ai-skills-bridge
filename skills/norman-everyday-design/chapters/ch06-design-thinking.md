# 第 6 章：设计思维 / Design Thinking

## 核心思想

优秀设计先确认正在解决正确的问题，再通过快速试验找到可用、可行且可持续的解法。

## 本章框架

- **Design Thinking / 设计思维**：先发现正确问题，再以发散和收敛循环寻找、验证解决方案。
  - 何时使用：当需求清单很确定，但团队对用户真实问题和成功标准缺少证据时。
  - 如何使用：观察并重构问题，发散多个解释，收敛到可验证的问题陈述；再发散方案、原型测试并迭代。
  - 失效方式：过早锁定需求或方案，让后续研究只能证明既定方向。
- **Double-Diamond / 双钻**：问题空间和方案空间各经历一次发散与收敛的过程模型。
  - 何时使用：当“设计思维 / Design Thinking”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Double-Diamond / 双钻”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Human-Centered Design**：从人的需要、能力与行为出发，通过观察、构思、原型和测试反复收敛的设计过程。
  - 何时使用：当“设计思维 / Design Thinking”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Human-Centered Design”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Conceptual Model / 概念模型**：用户据以预测系统行为的简化解释；界面应提供连贯的系统形象。
  - 何时使用：当“设计思维 / Design Thinking”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Conceptual Model / 概念模型”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Design Thinking / 设计思维**：先发现正确问题，再以发散和收敛循环寻找、验证解决方案。
- **Double-Diamond / 双钻**：问题空间和方案空间各经历一次发散与收敛的过程模型。
- **Human-Centered Design**：从人的需要、能力与行为出发，通过观察、构思、原型和测试反复收敛的设计过程。
- **Conceptual Model / 概念模型**：用户据以预测系统行为的简化解释；界面应提供连贯的系统形象。

## 心智模型

- 把本章看成一个决策过滤器：观察并重构问题，发散多个解释，收敛到可验证的问题陈述；再发散方案、原型测试并迭代。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **方案先行**：过早锁定需求或方案，让后续研究只能证明既定方向。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

“需要更大的门牌”可能并非真正问题。观察后发现访客在入口分叉处失去方向，于是问题从字号变成寻路系统；原型应同时测试空间分区、标志位置和反馈。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 观察并重构问题，发散多个解释，收敛到可验证的问题陈述；再发散方案、原型测试并迭代。
2. 把“Design Thinking / 设计思维”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Conceptual Model / 概念模型”，并记录失败条件。
