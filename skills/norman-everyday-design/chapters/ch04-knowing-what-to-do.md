# 第 4 章：知晓如何行动：约束、可发现性与反馈 / Knowing What to Do

## 核心思想

当概念模型不完整时，人仍可借助约束、映射、意符和反馈推断下一步。

## 本章框架

- **Constraints / 约束**：通过物理、文化、语义或逻辑关系限制不合适的行动。
  - 何时使用：当新用户必须无说明完成装配、设置或多步操作时。
  - 如何使用：先阻止不可能或危险动作，再让正确动作可见，最后让结果及时且与动作成比例地反馈。
  - 失效方式：依靠警告文案弥补本可由结构约束消除的错误。
- **Mapping / 映射**：控件、动作与结果之间的对应关系；自然映射减少解释和记忆。
  - 何时使用：当“知晓如何行动：约束、可发现性与反馈 / Knowing What to Do”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Mapping / 映射”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Feedback / 反馈**：及时、可解释地呈现行动已发生以及系统变成了什么状态。
  - 何时使用：当“知晓如何行动：约束、可发现性与反馈 / Knowing What to Do”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Feedback / 反馈”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Signifier / 意符**：传达何处以及如何行动的可感知线索。
  - 何时使用：当“知晓如何行动：约束、可发现性与反馈 / Knowing What to Do”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Signifier / 意符”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Constraints / 约束**：通过物理、文化、语义或逻辑关系限制不合适的行动。
- **Mapping / 映射**：控件、动作与结果之间的对应关系；自然映射减少解释和记忆。
- **Feedback / 反馈**：及时、可解释地呈现行动已发生以及系统变成了什么状态。
- **Signifier / 意符**：传达何处以及如何行动的可感知线索。

## 心智模型

- 把本章看成一个决策过滤器：先阻止不可能或危险动作，再让正确动作可见，最后让结果及时且与动作成比例地反馈。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **确认框泛滥**：依靠警告文案弥补本可由结构约束消除的错误。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

装一块只能以一个方向插入的组件：非对称形状提供物理约束，插槽位置提供映射，卡入声与状态灯提供反馈；三者共同减少说明书依赖。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 先阻止不可能或危险动作，再让正确动作可见，最后让结果及时且与动作成比例地反馈。
2. 把“Constraints / 约束”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Signifier / 意符”，并记录失败条件。
