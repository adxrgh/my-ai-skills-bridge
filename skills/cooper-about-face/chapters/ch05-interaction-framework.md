# 第 5 章：设计产品：框架和提炼

## 核心思想

先确定结构、关系和关键路径，再进入控件与像素，避免局部细节锁死整体。

## 本章框架

- **Interaction Framework / 交互框架**：在细节控件前定义产品姿态、屏幕关系、功能分组、关键路径和输入输出。
  - 何时使用：当团队有大量页面草图却没有稳定产品模型时。
  - 如何使用：定义外形与姿态、功能和数据分组、层级与关键路径；验证后再细化状态、术语和视觉。
  - 失效方式：一开始就高保真，导致团队围绕颜色而非行为争论。
- **Refinement / 提炼**：在框架稳定后完善行为、视觉、术语、状态和边界情况。
  - 何时使用：当“设计产品：框架和提炼”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Refinement / 提炼”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Interaction Pattern / 交互模式**：对反复出现问题的情境化解决结构，记录适用条件和权衡。
  - 何时使用：当“设计产品：框架和提炼”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Interaction Pattern / 交互模式”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Interaction Framework / 交互框架**：在细节控件前定义产品姿态、屏幕关系、功能分组、关键路径和输入输出。
- **Refinement / 提炼**：在框架稳定后完善行为、视觉、术语、状态和边界情况。
- **Interaction Pattern / 交互模式**：对反复出现问题的情境化解决结构，记录适用条件和权衡。

## 心智模型

- 把本章看成一个决策过滤器：定义外形与姿态、功能和数据分组、层级与关键路径；验证后再细化状态、术语和视觉。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **细节早熟**：一开始就高保真，导致团队围绕颜色而非行为争论。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

先确定病历工作区、患者上下文和订单流程的关系，再设计每个表格控件与视觉规范。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 定义外形与姿态、功能和数据分组、层级与关键路径；验证后再细化状态、术语和视觉。
2. 把“Interaction Framework / 交互框架”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Interaction Pattern / 交互模式”，并记录失败条件。
