# 第 20 章：网页的设计

## 核心思想

Web 的页面、链接、滚动和跨设备特性要求清晰寻路并保护任务状态。

## 本章框架

- **Web Interaction / Web 交互**：在页面、滚动、寻路、链接与跨设备约束下维持状态和任务连续性。
  - 何时使用：当设计内容网站或 Web 应用的信息架构与流程时。
  - 如何使用：保持位置与导航可见，链接行为一致，长流程保存状态，并分别处理页面浏览与应用工作。
  - 失效方式：在应用中模拟网站跳转，或在网站中隐藏浏览路径。
- **Platform Convention / 平台约定**：用户从操作系统和设备生态带来的稳定预期，偏离需有明确收益。
  - 何时使用：当“网页的设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Platform Convention / 平台约定”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Orchestration and Flow / 编配与流**：让动作、状态、反馈和过渡形成连续、和谐且少打断的体验。
  - 何时使用：当“网页的设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Orchestration and Flow / 编配与流”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Web Interaction / Web 交互**：在页面、滚动、寻路、链接与跨设备约束下维持状态和任务连续性。
- **Platform Convention / 平台约定**：用户从操作系统和设备生态带来的稳定预期，偏离需有明确收益。
- **Orchestration and Flow / 编配与流**：让动作、状态、反馈和过渡形成连续、和谐且少打断的体验。

## 心智模型

- 把本章看成一个决策过滤器：保持位置与导航可见，链接行为一致，长流程保存状态，并分别处理页面浏览与应用工作。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **页面迷宫**：在应用中模拟网站跳转，或在网站中隐藏浏览路径。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

申请流程即使刷新或返回也保留数据，并显示步骤与错误位置；内容页提供稳定链接和层级路径。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 保持位置与导航可见，链接行为一致，长流程保存状态，并分别处理页面浏览与应用工作。
2. 把“Web Interaction / Web 交互”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Orchestration and Flow / 编配与流”，并记录失败条件。
