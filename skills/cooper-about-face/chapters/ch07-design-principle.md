# 第 7 章：良好产品行为的基础

## 核心思想

原则和模式将经验转为可复用判断，但必须在具体人物目标和情境中解释。

## 本章框架

- **Design Principle / 设计原则**：跨具体界面复用的行为判断规则，用来约束方案而非替代情境。
  - 何时使用：当团队反复解决相似问题或标准不一致时。
  - 如何使用：记录问题、适用情境、解决结构和权衡；评审时说明原则如何服务当前目标。
  - 失效方式：把模式库当控件目录或把原则当绝对规则。
- **Interaction Pattern / 交互模式**：对反复出现问题的情境化解决结构，记录适用条件和权衡。
  - 何时使用：当“良好产品行为的基础”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Interaction Pattern / 交互模式”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Goals / 目标**：人希望达到的终态，包括体验目标、最终目标与人生目标；任务只是达到目标的手段。
  - 何时使用：当“良好产品行为的基础”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Goals / 目标”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Design Principle / 设计原则**：跨具体界面复用的行为判断规则，用来约束方案而非替代情境。
- **Interaction Pattern / 交互模式**：对反复出现问题的情境化解决结构，记录适用条件和权衡。
- **Goals / 目标**：人希望达到的终态，包括体验目标、最终目标与人生目标；任务只是达到目标的手段。

## 心智模型

- 把本章看成一个决策过滤器：记录问题、适用情境、解决结构和权衡；评审时说明原则如何服务当前目标。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **模式拼装**：把模式库当控件目录或把原则当绝对规则。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

“提供概览再给细节”适合复杂数据探索，但紧急单一动作可能需要直接呈现关键决定。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 记录问题、适用情境、解决结构和权衡；评审时说明原则如何服务当前目标。
2. 把“Design Principle / 设计原则”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Goals / 目标”，并记录失败条件。
