# 第 9 章：平台和姿态

## 核心思想

产品姿态由使用持续时间、注意力和平台决定，进而约束导航、反馈与密度。

## 本章框架

- **Posture / 姿态**：产品在用户注意、使用持续时间和工作环境中的总体行为姿态。
  - 何时使用：当同一界面被机械搬到桌面、Web、手机或信息亭时。
  - 如何使用：先判断独占、暂时、后台等姿态，再结合平台约定决定结构和行为。
  - 失效方式：把响应式尺寸变化误当跨平台设计。
- **Platform Convention / 平台约定**：用户从操作系统和设备生态带来的稳定预期，偏离需有明确收益。
  - 何时使用：当“平台和姿态”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Platform Convention / 平台约定”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Mobile Posture / 移动姿态**：围绕触控、有限空间、短时与情境变化组织导航和动作。
  - 何时使用：当“平台和姿态”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Mobile Posture / 移动姿态”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Posture / 姿态**：产品在用户注意、使用持续时间和工作环境中的总体行为姿态。
- **Platform Convention / 平台约定**：用户从操作系统和设备生态带来的稳定预期，偏离需有明确收益。
- **Mobile Posture / 移动姿态**：围绕触控、有限空间、短时与情境变化组织导航和动作。

## 心智模型

- 把本章看成一个决策过滤器：先判断独占、暂时、后台等姿态，再结合平台约定决定结构和行为。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **一套界面走天下**：把响应式尺寸变化误当跨平台设计。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

桌面分析工具可保持高密度工作区，手机伴侣则聚焦查看异常和快速确认，而不是缩小全部面板。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 先判断独占、暂时、后台等姿态，再结合平台约定决定结构和行为。
2. 把“Posture / 姿态”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Mobile Posture / 移动姿态”，并记录失败条件。
