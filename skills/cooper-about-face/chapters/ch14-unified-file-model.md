# 第 14 章：重新思考数据输入、存储与检索

## 核心思想

传统文件和保存机制把实现模型暴露给人；系统应持续保护工作并按人的方式支持检索。

## 本章框架

- **Unified File Model / 统一文件模型**：减少打开、保存和文件位置管理，让系统持续保存且保留版本。
  - 何时使用：当用户频繁管理保存、版本、路径和格式时。
  - 如何使用：自动保存、保留版本、按内容与关系检索，并让导出成为明确的共享动作。
  - 失效方式：隐藏存储状态或锁死数据，造成新的不透明。
- **Eliminate Excise / 消除负担**：移除不直接推进用户目标的导航、记忆、配置、确认和机械步骤。
  - 何时使用：当“重新思考数据输入、存储与检索”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Eliminate Excise / 消除负担”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Mental Model / 心理模型**：用户对对象、任务与因果的内部理解，界面应优先贴近它而非实现模型。
  - 何时使用：当“重新思考数据输入、存储与检索”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Mental Model / 心理模型”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Unified File Model / 统一文件模型**：减少打开、保存和文件位置管理，让系统持续保存且保留版本。
- **Eliminate Excise / 消除负担**：移除不直接推进用户目标的导航、记忆、配置、确认和机械步骤。
- **Mental Model / 心理模型**：用户对对象、任务与因果的内部理解，界面应优先贴近它而非实现模型。

## 心智模型

- 把本章看成一个决策过滤器：自动保存、保留版本、按内容与关系检索，并让导出成为明确的共享动作。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **软盘时代模型**：隐藏存储状态或锁死数据，造成新的不透明。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

笔记应用持续保存编辑并提供历史；用户按标题、内容和时间找回，只有导出时才选择文件格式。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 自动保存、保留版本、按内容与关系检索，并让导出成为明确的共享动作。
2. 把“Unified File Model / 统一文件模型”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Mental Model / 心理模型”，并记录失败条件。
