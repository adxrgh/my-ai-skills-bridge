# 第 19 章：为移动设备和其他设备而设计

## 核心思想

移动和专用设备受触控、姿势、注意力、环境与硬件能力约束，必须按情境重构。

## 本章框架

- **Mobile Posture / 移动姿态**：围绕触控、有限空间、短时与情境变化组织导航和动作。
  - 何时使用：当功能进入手机、平板、信息亭、汽车或语音设备时。
  - 如何使用：识别核心情境与输入方式，保证目标尺寸、反馈、单手与无障碍，并尊重平台习惯。
  - 失效方式：把桌面控件缩小或创造无提示手势。
- **Platform Convention / 平台约定**：用户从操作系统和设备生态带来的稳定预期，偏离需有明确收益。
  - 何时使用：当“为移动设备和其他设备而设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Platform Convention / 平台约定”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Accessibility / 无障碍**：把不同感知、运动和认知需求纳入人物模型、流程与细节。
  - 何时使用：当“为移动设备和其他设备而设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Accessibility / 无障碍”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Mobile Posture / 移动姿态**：围绕触控、有限空间、短时与情境变化组织导航和动作。
- **Platform Convention / 平台约定**：用户从操作系统和设备生态带来的稳定预期，偏离需有明确收益。
- **Accessibility / 无障碍**：把不同感知、运动和认知需求纳入人物模型、流程与细节。

## 心智模型

- 把本章看成一个决策过滤器：识别核心情境与输入方式，保证目标尺寸、反馈、单手与无障碍，并尊重平台习惯。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **微缩桌面**：把桌面控件缩小或创造无提示手势。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

汽车界面限制驾驶中复杂输入，用大目标和语音辅助；停车后才开放完整设置。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 识别核心情境与输入方式，保证目标尺寸、反馈、单手与无障碍，并尊重平台习惯。
2. 把“Mobile Posture / 移动姿态”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Accessibility / 无障碍”，并记录失败条件。
