# 第 15 章：防止错误、通知决定

## 核心思想

优先预防和可逆操作，用非模态反馈表达问题；警告与确认应是最后手段。

## 本章框架

- **Error Prevention / 防错**：通过约束、清晰映射、预览、撤销和非模态反馈避免或减轻错误。
  - 何时使用：当产品用大量错误框和“你确定吗”保障安全时。
  - 如何使用：约束无效动作、提供预览和撤销、持续显示影响；只有高风险不可逆节点才确认。
  - 失效方式：确认疲劳让人机械点击。
- **Undo / 撤销**：依据用户心理模型恢复操作结果，形成可逆历史而非只反转技术命令。
  - 何时使用：当“防止错误、通知决定”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Undo / 撤销”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Rich Visual Modeless Feedback / 富视觉非模态反馈**：在不中断工作流的情况下持续表达状态、范围和结果。
  - 何时使用：当“防止错误、通知决定”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Rich Visual Modeless Feedback / 富视觉非模态反馈”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Error Prevention / 防错**：通过约束、清晰映射、预览、撤销和非模态反馈避免或减轻错误。
- **Undo / 撤销**：依据用户心理模型恢复操作结果，形成可逆历史而非只反转技术命令。
- **Rich Visual Modeless Feedback / 富视觉非模态反馈**：在不中断工作流的情况下持续表达状态、范围和结果。

## 心智模型

- 把本章看成一个决策过滤器：约束无效动作、提供预览和撤销、持续显示影响；只有高风险不可逆节点才确认。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **警告框安全**：确认疲劳让人机械点击。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

删除文件先移入可恢复废纸篓并提供撤销；只有永久清除且影响明确时再确认。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 约束无效动作、提供预览和撤销、持续显示影响；只有高风险不可逆节点才确认。
2. 把“Error Prevention / 防错”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Rich Visual Modeless Feedback / 富视觉非模态反馈”，并记录失败条件。
