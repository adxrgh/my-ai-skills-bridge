# 第 18 章：为桌面应用而设计

## 核心思想

桌面环境适合长时、精细和多对象工作，需要稳定窗口、选择、菜单与直接操作模型。

## 本章框架

- **Desktop Posture / 桌面姿态**：围绕长时、精细、窗口化工作设计命令、选择和对象操作。
  - 何时使用：当设计生产力或专业桌面工具时。
  - 如何使用：围绕主窗口和工作对象组织命令，支持选择、拖放、键盘和多窗口状态，遵守平台约定。
  - 失效方式：用网页卡片模式取代高效桌面工作流。
- **Platform Convention / 平台约定**：用户从操作系统和设备生态带来的稳定预期，偏离需有明确收益。
  - 何时使用：当“为桌面应用而设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Platform Convention / 平台约定”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Direct Manipulation / 直接操作**：对可见对象进行连续、可逆、快速反馈的操作。
  - 何时使用：当“为桌面应用而设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Direct Manipulation / 直接操作”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Desktop Posture / 桌面姿态**：围绕长时、精细、窗口化工作设计命令、选择和对象操作。
- **Platform Convention / 平台约定**：用户从操作系统和设备生态带来的稳定预期，偏离需有明确收益。
- **Direct Manipulation / 直接操作**：对可见对象进行连续、可逆、快速反馈的操作。

## 心智模型

- 把本章看成一个决策过滤器：围绕主窗口和工作对象组织命令，支持选择、拖放、键盘和多窗口状态，遵守平台约定。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **平台失忆**：用网页卡片模式取代高效桌面工作流。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

素材管理器允许多选、键盘导航、拖放与独立检查器；窗口恢复上次工作状态。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 围绕主窗口和工作对象组织命令，支持选择、拖放、键盘和多窗口状态，遵守平台约定。
2. 把“Desktop Posture / 桌面姿态”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Direct Manipulation / 直接操作”，并记录失败条件。
