# 第 17 章：整合视觉设计

## 核心思想

视觉设计组织注意、结构与信息关系，应从人物目标和交互框架生长。

## 本章框架

- **Visual Hierarchy / 视觉层级**：用位置、大小、对比、分组和节奏表达结构与优先级。
  - 何时使用：当视觉稿漂亮但任务层级与状态不清时。
  - 如何使用：用形状、大小、位置、颜色、文字和动效表达优先级、分组、因果与状态，并控制视觉工作量。
  - 失效方式：品牌装饰覆盖行为层级或仅靠颜色传达。
- **Information Visualization / 信息可视化**：以适合比较、因果、模式和多变量理解的视觉编码呈现信息。
  - 何时使用：当“整合视觉设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Information Visualization / 信息可视化”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Goals / 目标**：人希望达到的终态，包括体验目标、最终目标与人生目标；任务只是达到目标的手段。
  - 何时使用：当“整合视觉设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Goals / 目标”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Visual Hierarchy / 视觉层级**：用位置、大小、对比、分组和节奏表达结构与优先级。
- **Information Visualization / 信息可视化**：以适合比较、因果、模式和多变量理解的视觉编码呈现信息。
- **Goals / 目标**：人希望达到的终态，包括体验目标、最终目标与人生目标；任务只是达到目标的手段。

## 心智模型

- 把本章看成一个决策过滤器：用形状、大小、位置、颜色、文字和动效表达优先级、分组、因果与状态，并控制视觉工作量。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **视觉皮肤**：品牌装饰覆盖行为层级或仅靠颜色传达。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

监控面板先突出需行动的异常及影响，再提供趋势和细节；品牌色不应与状态色竞争。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 用形状、大小、位置、颜色、文字和动效表达优先级、分组、因果与状态，并控制视觉工作量。
2. 把“Visual Hierarchy / 视觉层级”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Goals / 目标”，并记录失败条件。
