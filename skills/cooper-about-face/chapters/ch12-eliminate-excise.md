# 第 12 章：减少工作，消除负担

## 核心思想

不推进用户目标的导航、记忆、配置和机械操作都是应被削减的负担。

## 本章框架

- **Eliminate Excise / 消除负担**：移除不直接推进用户目标的导航、记忆、配置、确认和机械步骤。
  - 何时使用：当完成简单目标需要多次搬运、定位或确认时。
  - 如何使用：把每一步标为目标任务或负担；通过记忆、默认、合并、直接入口和更好映射消除负担。
  - 失效方式：只减少点击数，却增加判断和错误风险。
- **Goal-Directed Task / 目标导向任务**：直接推进用户目标的活动。
  - 何时使用：当“减少工作，消除负担”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Goal-Directed Task / 目标导向任务”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Progressive Disclosure / 渐进式展开**：保留常用能力的直接可见性，按需暴露高级复杂性。
  - 何时使用：当“减少工作，消除负担”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Progressive Disclosure / 渐进式展开”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Eliminate Excise / 消除负担**：移除不直接推进用户目标的导航、记忆、配置、确认和机械步骤。
- **Goal-Directed Task / 目标导向任务**：直接推进用户目标的活动。
- **Progressive Disclosure / 渐进式展开**：保留常用能力的直接可见性，按需暴露高级复杂性。

## 心智模型

- 把本章看成一个决策过滤器：把每一步标为目标任务或负担；通过记忆、默认、合并、直接入口和更好映射消除负担。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **点击数崇拜**：只减少点击数，却增加判断和错误风险。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

报销系统自动带入员工与项目数据，只要求上传凭证和确认例外，而不重复填写组织已知信息。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 把每一步标为目标任务或负担；通过记忆、默认、合并、直接入口和更好映射消除负担。
2. 把“Eliminate Excise / 消除负担”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Progressive Disclosure / 渐进式展开”，并记录失败条件。
