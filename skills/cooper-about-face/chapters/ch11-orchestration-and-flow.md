# 第 11 章：编配与流

## 核心思想

和谐交互让工具、状态和反馈围绕任务连续展开，尽量不打断人的思路。

## 本章框架

- **Orchestration and Flow / 编配与流**：让动作、状态、反馈和过渡形成连续、和谐且少打断的体验。
  - 何时使用：当流程充满模态框、页面跳转和状态丢失时。
  - 如何使用：按心理模型组织对象与动作，提供选择而非审问，用非模态反馈维持上下文。
  - 失效方式：每一步都要求确认或切换页面。
- **Mental Model / 心理模型**：用户对对象、任务与因果的内部理解，界面应优先贴近它而非实现模型。
  - 何时使用：当“编配与流”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Mental Model / 心理模型”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Rich Visual Modeless Feedback / 富视觉非模态反馈**：在不中断工作流的情况下持续表达状态、范围和结果。
  - 何时使用：当“编配与流”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Rich Visual Modeless Feedback / 富视觉非模态反馈”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Orchestration and Flow / 编配与流**：让动作、状态、反馈和过渡形成连续、和谐且少打断的体验。
- **Mental Model / 心理模型**：用户对对象、任务与因果的内部理解，界面应优先贴近它而非实现模型。
- **Rich Visual Modeless Feedback / 富视觉非模态反馈**：在不中断工作流的情况下持续表达状态、范围和结果。

## 心智模型

- 把本章看成一个决策过滤器：按心理模型组织对象与动作，提供选择而非审问，用非模态反馈维持上下文。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **对话框编排**：每一步都要求确认或切换页面。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

图片编辑中，调整直接作用于可见对象并实时预览；保存状态在背景表达，不反复询问文件路径。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 按心理模型组织对象与动作，提供选择而非审问，用非模态反馈维持上下文。
2. 把“Orchestration and Flow / 编配与流”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Rich Visual Modeless Feedback / 富视觉非模态反馈”，并记录失败条件。
