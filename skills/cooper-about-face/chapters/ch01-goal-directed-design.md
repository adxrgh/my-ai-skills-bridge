# 第 1 章：数字产品的设计过程

## 核心思想

数字产品的行为必须被有意识地设计；目标导向过程把研究证据一路连接到产品细节。

## 本章框架

- **Goal-Directed Design / 目标导向设计**：以研究得到的人物模型及其目标驱动需求、框架与细节设计的完整过程。
  - 何时使用：当需求主要由市场清单和技术能力组成时。
  - 如何使用：按研究、建模、需求、框架、提炼和支持阶段推进，每个设计决定回链到人物目标。
  - 失效方式：让开发过程自然“长出”交互，或把设计降为视觉装饰。
- **Goals / 目标**：人希望达到的终态，包括体验目标、最终目标与人生目标；任务只是达到目标的手段。
  - 何时使用：当“数字产品的设计过程”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Goals / 目标”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Interaction Framework / 交互框架**：在细节控件前定义产品姿态、屏幕关系、功能分组、关键路径和输入输出。
  - 何时使用：当“数字产品的设计过程”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Interaction Framework / 交互框架”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Goal-Directed Design / 目标导向设计**：以研究得到的人物模型及其目标驱动需求、框架与细节设计的完整过程。
- **Goals / 目标**：人希望达到的终态，包括体验目标、最终目标与人生目标；任务只是达到目标的手段。
- **Interaction Framework / 交互框架**：在细节控件前定义产品姿态、屏幕关系、功能分组、关键路径和输入输出。

## 心智模型

- 把本章看成一个决策过滤器：按研究、建模、需求、框架、提炼和支持阶段推进，每个设计决定回链到人物目标。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **功能与实现驱动**：让开发过程自然“长出”交互，或把设计降为视觉装饰。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

团队不从“加仪表盘”开始，而先确认运营人员的目标与决策；由此推导需要的信息、频率、状态和行动入口。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 按研究、建模、需求、框架、提炼和支持阶段推进，每个设计决定回链到人物目标。
2. 把“Goal-Directed Design / 目标导向设计”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Interaction Framework / 交互框架”，并记录失败条件。
