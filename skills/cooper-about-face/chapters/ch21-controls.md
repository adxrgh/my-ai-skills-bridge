# 第 21 章：设计细节：控件和对话框

## 核心思想

控件应匹配选择、输入、命令和显示语义；对话框只承担必要的集中决定。

## 本章框架

- **Controls / 控件**：供选择、输入、命令和显示的界面构件，其行为应与目标、状态和风险匹配。
  - 何时使用：当细化表单、设置、列表和高风险操作时。
  - 如何使用：按数据类型、选项数量、频率和风险选择控件；保持标签、默认、状态、验证与键盘行为一致。
  - 失效方式：为每个动作发明新控件，或用模态框承载常规流程。
- **Dialogs / 对话框**：用于必要的集中交互或关键决定；不应成为常规流程和错误报告的垃圾场。
  - 何时使用：当“设计细节：控件和对话框”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Dialogs / 对话框”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Error Prevention / 防错**：通过约束、清晰映射、预览、撤销和非模态反馈避免或减轻错误。
  - 何时使用：当“设计细节：控件和对话框”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Error Prevention / 防错”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Controls / 控件**：供选择、输入、命令和显示的界面构件，其行为应与目标、状态和风险匹配。
- **Dialogs / 对话框**：用于必要的集中交互或关键决定；不应成为常规流程和错误报告的垃圾场。
- **Error Prevention / 防错**：通过约束、清晰映射、预览、撤销和非模态反馈避免或减轻错误。

## 心智模型

- 把本章看成一个决策过滤器：按数据类型、选项数量、频率和风险选择控件；保持标签、默认、状态、验证与键盘行为一致。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **控件动物园**：为每个动作发明新控件，或用模态框承载常规流程。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

少量互斥选项用单选直接展示，多项独立选择用复选；验证靠近字段且不清空输入，普通成功用非模态反馈。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 按数据类型、选项数量、频率和风险选择控件；保持标签、默认、状态、验证与键盘行为一致。
2. 把“Controls / 控件”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Error Prevention / 防错”，并记录失败条件。
