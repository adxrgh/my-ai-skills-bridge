# 第 16 章：为不同的需求而设计

## 核心思想

不同能力、经验、语言和情境需要在核心模型内被支持，而非事后增加补丁。

## 本章框架

- **Learnability / 易学性**：通过清晰模型、渐进暴露、上下文帮助和一致行为支持掌握。
  - 何时使用：当产品准备本地化、定制、帮助或无障碍适配时。
  - 如何使用：把差异纳入人物模型与框架，保持核心一致，允许适度配置并提供上下文帮助。
  - 失效方式：无限定制把设计责任转给用户。
- **Accessibility / 无障碍**：把不同感知、运动和认知需求纳入人物模型、流程与细节。
  - 何时使用：当“为不同的需求而设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Accessibility / 无障碍”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Progressive Disclosure / 渐进式展开**：保留常用能力的直接可见性，按需暴露高级复杂性。
  - 何时使用：当“为不同的需求而设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Progressive Disclosure / 渐进式展开”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Learnability / 易学性**：通过清晰模型、渐进暴露、上下文帮助和一致行为支持掌握。
- **Accessibility / 无障碍**：把不同感知、运动和认知需求纳入人物模型、流程与细节。
- **Progressive Disclosure / 渐进式展开**：保留常用能力的直接可见性，按需暴露高级复杂性。

## 心智模型

- 把本章看成一个决策过滤器：把差异纳入人物模型与框架，保持核心一致，允许适度配置并提供上下文帮助。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **设置即包容**：无限定制把设计责任转给用户。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

数据工具提供清晰默认工作区、键盘和屏幕阅读支持，并允许角色相关布局，而不是给出几十个无解释选项。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 把差异纳入人物模型与框架，保持核心一致，允许适度配置并提供上下文帮助。
2. 把“Learnability / 易学性”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Progressive Disclosure / 渐进式展开”，并记录失败条件。
