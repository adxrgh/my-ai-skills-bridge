# 第 1 章：小心翼翼的汽车和难以驾驭的厨房：机器如何主控

## 核心思想

自动化接管越多，人越容易失去对模式、目标和系统意图的理解。

## 本章框架

- **Automation / 自动化**：让机器在一定授权和条件下感知、判断或行动；其边界必须可理解。
  - 何时使用：当系统会主动纠正、拒绝或改变人的操作时。
  - 如何使用：让当前模式、触发原因、下一动作和接管方式持续可见。
  - 失效方式：只在系统出错后弹出解释，让用户平时无法建立预测。
- **Automation Surprise / 自动化惊奇**：系统行为与人的预期不一致，通常源于隐藏模式、目标或信息不对称。
  - 何时使用：当“小心翼翼的汽车和难以驾驭的厨房：机器如何主控”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Automation Surprise / 自动化惊奇”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Mode Awareness / 模式意识**：人对系统当前控制模式、权限和行为规则的理解。
  - 何时使用：当“小心翼翼的汽车和难以驾驭的厨房：机器如何主控”相关决策存在多个看似合理的选项时。

## 关键概念

- **Automation / 自动化**：让机器在一定授权和条件下感知、判断或行动；其边界必须可理解。
- **Automation Surprise / 自动化惊奇**：系统行为与人的预期不一致，通常源于隐藏模式、目标或信息不对称。
- **Mode Awareness / 模式意识**：人对系统当前控制模式、权限和行为规则的理解。

## 心智模型

- 把本章看成一个决策过滤器：让当前模式、触发原因、下一动作和接管方式持续可见。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **隐藏的主控权**：只在系统出错后弹出解释，让用户平时无法建立预测。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

车道保持系统主动转向时，应以方向盘反馈和仪表状态说明原因，并允许明确接管；不能让驾驶者猜是路面还是自动化在施力。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 让当前模式、触发原因、下一动作和接管方式持续可见。
2. 把“Automation / 自动化”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Mode Awareness / 模式意识”，并记录失败条件。
