# 第 5 章：自动化扮演的角色

## 核心思想

自动化应按风险、可预测性和可逆性选择角色，而不是一律追求完全接管。

## 本章框架

- **Automation / 自动化**：让机器在一定授权和条件下感知、判断或行动；其边界必须可理解。
  - 何时使用：当决定系统应建议、执行、监督还是自治时。
  - 如何使用：按错误代价、时间压力、可逆性和人类监督能力选择自动化等级，并设计升级与降级。
  - 失效方式：高风险场景中用默认自动执行换取表面效率。
- **Human-Machine Team / 人机团队**：把人和机器视为互补协作者，围绕共同目标分配能力和责任。
  - 何时使用：当“自动化扮演的角色”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Human-Machine Team / 人机团队”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Mode Awareness / 模式意识**：人对系统当前控制模式、权限和行为规则的理解。
  - 何时使用：当“自动化扮演的角色”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Mode Awareness / 模式意识”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Automation / 自动化**：让机器在一定授权和条件下感知、判断或行动；其边界必须可理解。
- **Human-Machine Team / 人机团队**：把人和机器视为互补协作者，围绕共同目标分配能力和责任。
- **Mode Awareness / 模式意识**：人对系统当前控制模式、权限和行为规则的理解。

## 心智模型

- 把本章看成一个决策过滤器：按错误代价、时间压力、可逆性和人类监督能力选择自动化等级，并设计升级与降级。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **自动化最大化**：高风险场景中用默认自动执行换取表面效率。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

邮件分类可自动执行且易恢复；药物剂量应以建议和核对为主，保留责任清晰的人类确认。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 按错误代价、时间压力、可逆性和人类监督能力选择自动化等级，并设计升级与降级。
2. 把“Automation / 自动化”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Mode Awareness / 模式意识”，并记录失败条件。
