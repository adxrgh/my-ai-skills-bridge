# 第 4 章：Transactional Tools

## 核心思想

确定任务通常更适合直接操作；语言应补充表达复杂意图，而不是取代所有控件。

## 本章框架

- **Transactional Tool**：围绕明确命令和确定结果工作的工具型交互。
  - 何时使用：当团队考虑把成熟工作流全部改成聊天。
  - 如何使用：按精度、可见选项、重复频率和可逆性选择直接操作或语言，并允许两者衔接。
  - 失效方式：聊天化一切，使状态、范围和批量操作变得不可见。
- **Conversational Interface**：通过语言协商目标和步骤的界面，适合表达含糊意图但不天然适合所有任务。
  - 何时使用：当“Transactional Tools”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Conversational Interface”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Multimodal Interaction**：把文字、视觉、直接操作、语音和系统行动组合起来，选择最适合当前信息的通道。
  - 何时使用：当“Transactional Tools”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Multimodal Interaction”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Transactional Tool**：围绕明确命令和确定结果工作的工具型交互。
- **Conversational Interface**：通过语言协商目标和步骤的界面，适合表达含糊意图但不天然适合所有任务。
- **Multimodal Interaction**：把文字、视觉、直接操作、语音和系统行动组合起来，选择最适合当前信息的通道。

## 心智模型

- 把本章看成一个决策过滤器：按精度、可见选项、重复频率和可逆性选择直接操作或语言，并允许两者衔接。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **Chat as UI everywhere**：聊天化一切，使状态、范围和批量操作变得不可见。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

筛选表格时，复杂条件可用自然语言起步，但解析结果应回显成可编辑筛选器，用户能看见实际条件。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 按精度、可见选项、重复频率和可逆性选择直接操作或语言，并允许两者衔接。
2. 把“Transactional Tool”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Multimodal Interaction”，并记录失败条件。
