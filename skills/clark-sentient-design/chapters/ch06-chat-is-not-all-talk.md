# 第 6 章：Chat Is Not All Talk

## 核心思想

复杂信息需要最合适的表现通道；优秀对话界面会在文字、结构化视图与直接操作间切换。

## 本章框架

- **Multimodal Interaction**：把文字、视觉、直接操作、语音和系统行动组合起来，选择最适合当前信息的通道。
  - 何时使用：当答案包含比较、空间、时间、数据或可编辑结果时。
  - 如何使用：判断信息最适合读、看、听还是操作，并让各通道共享同一状态。
  - 失效方式：把表格、地图和进度压成长段文字。
- **Observability**：让人能看到代理做了什么、基于什么、当前状态和接下来准备做什么。
  - 何时使用：当“Chat Is Not All Talk”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Observability”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Transactional Tool**：围绕明确命令和确定结果工作的工具型交互。
  - 何时使用：当“Chat Is Not All Talk”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Transactional Tool”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Multimodal Interaction**：把文字、视觉、直接操作、语音和系统行动组合起来，选择最适合当前信息的通道。
- **Observability**：让人能看到代理做了什么、基于什么、当前状态和接下来准备做什么。
- **Transactional Tool**：围绕明确命令和确定结果工作的工具型交互。

## 心智模型

- 把本章看成一个决策过滤器：判断信息最适合读、看、听还是操作，并让各通道共享同一状态。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **纯文字执念**：把表格、地图和进度压成长段文字。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

房产助手用对话收集偏好，用地图显示位置、卡片比较房源，并让地图选择反向更新对话上下文。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 判断信息最适合读、看、听还是操作，并让各通道共享同一状态。
2. 把“Multimodal Interaction”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Transactional Tool”，并记录失败条件。
