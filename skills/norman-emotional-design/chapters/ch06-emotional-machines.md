# 第 6 章：情感化机器

## 核心思想

机器表现情感会改变人的期待与关系，因此表达必须与真实能力和责任一致。

## 本章框架

- **Emotional Machines / 情感化机器**：能够感知、表达或调节情感线索的系统。
  - 何时使用：当产品使用声音、角色、语气或情绪识别时。
  - 如何使用：明确系统实际感知能力、表达目的和不确定性，避免制造虚假互惠。
  - 失效方式：用亲密语气诱导用户披露，而系统并不真正理解或承担关系义务。
- **Anthropomorphism / 拟人化**：人倾向于把意图和情感归因于会行动、回应的对象。
  - 何时使用：当“情感化机器”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Anthropomorphism / 拟人化”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Trust / 信任**：由能力、可预测性、诚意和可恢复性逐步形成的依赖判断。
  - 何时使用：当“情感化机器”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Trust / 信任”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Emotional Machines / 情感化机器**：能够感知、表达或调节情感线索的系统。
- **Anthropomorphism / 拟人化**：人倾向于把意图和情感归因于会行动、回应的对象。
- **Trust / 信任**：由能力、可预测性、诚意和可恢复性逐步形成的依赖判断。

## 心智模型

- 把本章看成一个决策过滤器：明确系统实际感知能力、表达目的和不确定性，避免制造虚假互惠。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **伪共情**：用亲密语气诱导用户披露，而系统并不真正理解或承担关系义务。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

健康助手可以说“我没有足够信息判断”，并提供人工支持；不应声称“我完全理解你的感受”来掩盖模型边界。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 明确系统实际感知能力、表达目的和不确定性，避免制造虚假互惠。
2. 把“Emotional Machines / 情感化机器”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Trust / 信任”，并记录失败条件。
