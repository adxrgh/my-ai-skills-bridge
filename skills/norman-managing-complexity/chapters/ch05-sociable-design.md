# 第 5 章：善于交际的设计

## 核心思想

产品应像好的协作者一样说明意图、尊重礼仪并让人预测其行为。

## 本章框架

- **Sociable Design / 善于交际的设计**：让产品以合乎礼仪、可理解并尊重关系的方式沟通意图和状态。
  - 何时使用：当自动化在没有解释或许可时打断、替用户行动时。
  - 如何使用：检查时机、语气、授权、可见状态和退出方式；让系统的“社交动作”符合关系。
  - 失效方式：用拟人文案掩盖强制行为和信息不对称。
- **Social Signifiers / 社会性意符**：由他人行为、痕迹和社会约定产生的行动线索。
  - 何时使用：当“善于交际的设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Social Signifiers / 社会性意符”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Partnership / 人机伙伴关系**：人负责目标、价值与例外判断，系统负责计算、记忆和稳定执行的互补分工。
  - 何时使用：当“善于交际的设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Partnership / 人机伙伴关系”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Sociable Design / 善于交际的设计**：让产品以合乎礼仪、可理解并尊重关系的方式沟通意图和状态。
- **Social Signifiers / 社会性意符**：由他人行为、痕迹和社会约定产生的行动线索。
- **Partnership / 人机伙伴关系**：人负责目标、价值与例外判断，系统负责计算、记忆和稳定执行的互补分工。

## 心智模型

- 把本章看成一个决策过滤器：检查时机、语气、授权、可见状态和退出方式；让系统的“社交动作”符合关系。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **表演式友好**：用拟人文案掩盖强制行为和信息不对称。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

会议助手准备录音时，应在加入前说明能力与数据范围，让所有参与者看到录制状态，并允许主持人与参与者拒绝。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 检查时机、语气、授权、可见状态和退出方式；让系统的“社交动作”符合关系。
2. 把“Sociable Design / 善于交际的设计”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Partnership / 人机伙伴关系”，并记录失败条件。
