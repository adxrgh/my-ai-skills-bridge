# 第 7 章：对等待的设计

## 核心思想

等待的痛苦由不确定、无解释、无控制和不公平放大，不只由时长决定。

## 本章框架

- **Designing Waiting / 等待设计**：通过预期、解释、进度、控制感和有价值活动改善等待体验。
  - 何时使用：当过程不可即时完成或时间波动很大时。
  - 如何使用：先给可信预期和原因，再展示有意义进度、保留选择，并及时更新变化。
  - 失效方式：用虚假进度条或乐观时间制造二次失望。
- **Journey / 旅程**：用户跨时间和触点完成目标的连续经历，而不是单个屏幕。
  - 何时使用：当“对等待的设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Journey / 旅程”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Sociable Design / 善于交际的设计**：让产品以合乎礼仪、可理解并尊重关系的方式沟通意图和状态。
  - 何时使用：当“对等待的设计”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Sociable Design / 善于交际的设计”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Designing Waiting / 等待设计**：通过预期、解释、进度、控制感和有价值活动改善等待体验。
- **Journey / 旅程**：用户跨时间和触点完成目标的连续经历，而不是单个屏幕。
- **Sociable Design / 善于交际的设计**：让产品以合乎礼仪、可理解并尊重关系的方式沟通意图和状态。

## 心智模型

- 把本章看成一个决策过滤器：先给可信预期和原因，再展示有意义进度、保留选择，并及时更新变化。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **伪进度**：用虚假进度条或乐观时间制造二次失望。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

上传大文件时显示已处理数量、剩余范围、后台继续条件和取消后果，比循环动画更能建立控制感。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 先给可信预期和原因，再展示有意义进度、保留选择，并及时更新变化。
2. 把“Designing Waiting / 等待设计”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Sociable Design / 善于交际的设计”，并记录失败条件。
