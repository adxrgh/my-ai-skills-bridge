# Chapter 1: The Generative Formula

## Core Idea

Designing programmes 的起点不是“如何做出这个形式”，而是“什么公式能够产生一组适当形式”。设计与 programme 互相依赖：programme 需要被设计，形式又由 programme 生成。

## Frameworks Introduced

- **The Formula Creates the Form**：先定义元素与组合规则，再让具体形式从规则中出现。
  - **When to use**：需要多个变体、长期扩展或避免每次从零开始的任务。
  - **How**：确定元素集合；规定组合、排列、转换和禁区；生成实例；根据结果反向修正规则。
  - **Why it works**：创造力被放在“可生成什么”这一更高层，而不被锁在一个成品中。

- **Elements + Rules = Programme**：一个 programme 至少包含可操作元素和它们的组合规则；必要时还要有评价条件。
  - **When to use**：团队把 programme 误解成视觉模板或自动化工具。
  - **How**：分别写出材料是什么、可以做哪些操作、如何判断输出。

- **Programme Superimposition**：复杂任务可能由多个 programme 叠加，如菜谱之上还有整套菜单的组织。
  - **How**：区分局部生成规则与更高层的协调规则，避免一个巨型规则承担所有问题。

## Key Concepts

- **Formula**：产生一组形式的关系规则。
- **Permutation**：保留元素、改变次序。
- **Constellation**：元素按规则形成的具体状态。
- **Rule of the game**：既允许变化又限制变化的操作协议。
- **Latent forms**：在组合空间中等待被发现、尚未实例化的形式。

## Mental Models

- 把 programme 想成郁金香球茎，具体形式是长出的花；创意集中在球茎的结构。
- 把设计师想成规则发明者兼结果编辑者，而不是随机输出的接受者。
- 用游戏、菜谱、针织、乐谱理解 programme：简单元素和规则可以产生丰富结果。

## Anti-patterns

- **Template mistaken for programme**：只允许替换内容，没有真正的关系变化。
- **Form first, rules later**：先做一个形式，再反向编造系统解释。
- **Rule fetish**：只因规则复杂而赞美它，不检查结果是否有意义。
- **Automation as authorship**：把执行交给机器后，也把选择和责任一并放弃。

## Worked Example

Paul Gredinger 用书名本身示范 programme。需要连接 design 与 programme 两个概念时，可以列举 Design of Programmes、Programme for Design、Design = Programme、Programming Designs、Designing Programmes 等关系。封面无法同时承载全部形式，于是选择其中一个标题，但这个标题代表背后完整的可能集合。

同样，具体诗把单词作为元素，以 permutation 为规则；Jass 纸牌把图形与数值作为元素，以游戏规则规定合法组合；针织把有限动作转化为二维或空间图样。结果不同，programme 的结构相同：定义材料，设计组合关系。

## Key Takeaways

1. Programme 的对象是可能形式的集合，而不只是一个成品。
2. 公式应足以生成差异，却必须为结果保留结构身份。
3. 设计规则本身是创造活动，不是创作后的行政整理。
4. 多层任务需要多个相互协调的 programme。
5. 执行可以自动化，选择与评价仍属于设计责任。
