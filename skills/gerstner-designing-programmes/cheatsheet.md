# Gerstner Decision Cheatsheet

## First Diagnosis

| 现象 | Gerstner 式动作 | 原因 |
|---|---|---|
| 争论停留在“更好看” | 补评价条件 | 最佳解只在条件中成立 |
| 方案只围绕一个想法微调 | 建 morphological box | 可能性被习惯提前封闭 |
| 所有输出都像同一模板 | 扩大变量与联动规则 | programme 应适应情境 |
| 输出彼此毫无关系 | 加强常量或不变量 | 变化没有结构身份 |
| 网格只能生成一种版式 | 重建比例关系 | 静态线框不是 programme |
| 动画中间态尴尬 | 设计连续性与步长 | 起点终点正确仍不够 |
| 生成结果很多但没区别 | 减少随机，增加秩序原则 | chance 常产生无性格差异 |
| 排版只是内容包装 | 同时编辑语言与形式 | integral typography 要求互相渗透 |
| 新媒介不断加例外 | 扩充或重构参数 | programme 没覆盖真实问题 |

## Programme Builder

1. **Problem**：要解决什么，不只是要制作什么？
2. **Elements**：可操作的基本材料是什么？
3. **Parameters**：哪些维度决定结果？
4. **Components**：各维度有哪些合法值？
5. **Constants**：什么一变就失去身份或功能？
6. **Variants**：什么不变就无法适应场景？
7. **Rules**：元素怎样排列、转换、重复或互相影响？
8. **Criteria**：为什么在当前条件下选这个结果？
9. **Process**：怎样生产、部署、维护和重新组合？
10. **Feedback**：哪个新经验应成为下一轮参数？

## Choose the Structure

| 问题类型 | 优先结构 |
|---|---|
| 多个独立维度 | Morphological box |
| 多种栏数和内容密度 | Proportional grid |
| 同一对象的多角度表达 | Programmed viewpoints |
| 状态连续变化 | Ordered series / transformation |
| 同元素的不同关系 | Permutation |
| 需要不可重复输出 | Rule-governed chance |
| 多触点品牌 | Constant-variant grammar |
| 工业化与长期变化 | Modular process |
| 观看者参与 | Participatory constellation |

## Order vs Chance

- 需要明确性格 → 增加可描述的秩序。
- 需要不可预测 → 只随机化指定参数。
- 输出虽不同却难区分 → 随机过多。
- 输出过于机械 → 引入受控扰动或新参数。
- 无法说明哪些关系必须保留 → 暂停生成，先定义结构。

## Integral Typography Audit

| Level | 通过标准 |
|---|---|
| 字母 → 词 | 构形强化词义、声音或节奏且保持可读 |
| 词 → 句 | 语言与视觉层级共同建立关系 |
| 句 → reading-time | 展开、翻页或顺序改变理解 |
| 任务 → 系统 | 各实例适配用途，同时显露共同 physiognomy |

## Acceptance Test

- 规则能生成未展示过的新实例吗？
- 每个参数都来自真实问题，而非为了增加变化吗？
- 常量是核心关系，还是随手固定的样式值？
- 极端内容、比例和媒介下仍能工作吗？
- 生产过程支持变化，还是每次都要重新手工修补？
- chance 的范围是否清楚？
- 观看者、使用者或维护者得到的是自由，还是额外负担？
- 新反馈会改善 programme，还是只增加例外？
