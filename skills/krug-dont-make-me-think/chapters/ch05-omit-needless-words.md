# 第 5 章：Omit Needless Words

## 核心思想

删掉无用文字能突出重要内容、降低滚动并改善扫描。

## 本章框架

- **Omit Needless Words**：删除不服务任务、解释或信任的文字，降低噪声和滚动。
  - 何时使用：当页面像说明书或营销稿，而用户只想完成任务时。
  - 如何使用：逐句问是否帮助行动、理解或信任；优先改界面以消除说明。
  - 失效方式：把所有文字都删成含糊图标。
- **Happy Talk / 欢迎废话**：自我介绍、营销式欢迎和没有用户价值的填充文字。
  - 何时使用：当“Omit Needless Words”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Happy Talk / 欢迎废话”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Instructions / 说明**：只有当界面无法自明且不能通过改造消除困惑时才保留的最短指导。
  - 何时使用：当“Omit Needless Words”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Instructions / 说明”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Omit Needless Words**：删除不服务任务、解释或信任的文字，降低噪声和滚动。
- **Happy Talk / 欢迎废话**：自我介绍、营销式欢迎和没有用户价值的填充文字。
- **Instructions / 说明**：只有当界面无法自明且不能通过改造消除困惑时才保留的最短指导。

## 心智模型

- 把本章看成一个决策过滤器：逐句问是否帮助行动、理解或信任；优先改界面以消除说明。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **无差别极简**：把所有文字都删成含糊图标。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

表单顶部的欢迎段落可删；把真正限制写在对应字段旁，并用示例直接表达格式。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 逐句问是否帮助行动、理解或信任；优先改界面以消除说明。
2. 把“Omit Needless Words”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Instructions / 说明”，并记录失败条件。
