# 第 7 章：The Big Bang Theory of Web Design

## 核心思想

首页必须快速解释这是什么、有什么价值、从哪里开始，同时处理内部利益竞争。

## 本章框架

- **Home Page Mission**：首页要同时表达身份、价值、内容范围、入口与可信度。
  - 何时使用：当首页成为所有部门堆放内容的地方时。
  - 如何使用：冻结身份、价值主张、主要入口和可信线索，再按用户优先级分配剩余空间。
  - 失效方式：用轮播图轮流满足利益相关者，却让用户无法建立重点。
- **Clear Visual Hierarchy**：用大小、位置、分组和一致性表达重要性与关系。
  - 何时使用：当“The Big Bang Theory of Web Design”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Clear Visual Hierarchy”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。
- **Stakeholder Conflict**：不同部门把首页当稀缺宣传位，导致共同目标被局部利益挤压。
  - 何时使用：当“The Big Bang Theory of Web Design”相关决策存在多个看似合理的选项时。
  - 如何使用：先标出用户目标与约束，再用“Stakeholder Conflict”逐项检查方案；无法观察或验证的判断不算完成。
  - 失效方式：把术语当标签，却没有改变产品行为或验证方法。

## 关键概念

- **Home Page Mission**：首页要同时表达身份、价值、内容范围、入口与可信度。
- **Clear Visual Hierarchy**：用大小、位置、分组和一致性表达重要性与关系。
- **Stakeholder Conflict**：不同部门把首页当稀缺宣传位，导致共同目标被局部利益挤压。

## 心智模型

- 把本章看成一个决策过滤器：冻结身份、价值主张、主要入口和可信线索，再按用户优先级分配剩余空间。
- 当局部界面“看起来合理”却让人迟疑时，回到用户目标、情境和反馈链，而不是继续装饰表面。
- 设计主张必须能被研究证据、行为结果或可用性观察推翻；不能被推翻的主张只是偏好。

## 反模式

- **首页大杂烩**：用轮播图轮流满足利益相关者，却让用户无法建立重点。
- **术语替代证据**：引用框架名称却没有说明用户、任务、约束和验证信号，会让团队产生虚假的确定性。

## Worked Example

新访客在几秒内应能说出产品用途和下一步；老用户的登录入口也必须稳定可见。

把例子重新应用到自己的产品时，保留同样的推理顺序：先写目标与情境，再写设计动作，最后写可观察的成功/失败信号。

## 关键结论

1. 冻结身份、价值主张、主要入口和可信线索，再按用户优先级分配剩余空间。
2. 把“Home Page Mission”落实为可观察的界面或流程行为，而不是停留在口号。
3. 用真实情境检查“Stakeholder Conflict”，并记录失败条件。
